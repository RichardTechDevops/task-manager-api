## 2. 本地启动 API

```bash
# 进入项目目录
cd /path/to/task-manager-api

# 创建并激活虚拟环境（Windows PowerShell 用下面第二行）
python -m venv .venv
.venv\Scripts\Activate.ps1
# macOS / Ubuntu:
# source .venv/bin/activate

# 安装运行依赖和 pylint
pip install -r requirements-dev.txt

# 启动服务，监听所有网卡的 8080
uvicorn src.app:app --host 0.0.0.0 --port 8080
```

可选环境变量：

```bash
# 改端口（作业默认 8080）
set PORT=8080
# 改日志级别：DEBUG / INFO / WARNING / ERROR
set LOG_LEVEL=INFO
```

macOS / Ubuntu 用 `export PORT=8080`。

浏览器打开：

- 健康检查：http://localhost:8080/health
- Swagger：http://localhost:8080/docs
- ReDoc：http://localhost:8080/redoc
- OpenAPI：http://localhost:8080/openapi.json

代码风格检查：

```bash
pylint src --fail-under=8.0
```

## 3. 用 curl 验证接口

下面每条都可以直接复制。先保证服务已在 8080 启动。

```bash
# 1) 健康检查，期望 200 和 {"status":"ok"}
curl http://localhost:8080/health

# 2) 列表，刚启动时应为 []
curl http://localhost:8080/tasks

# 3) 创建任务，期望 201
curl -X POST http://localhost:8080/tasks \
  -H "Content-Type: application/json" \
  -d "{\"title\":\"Write docs\",\"description\":\"Draft README\",\"status\":\"todo\"}"

# 4) 把上一步返回的 id 换成真实 UUID 再查
curl http://localhost:8080/tasks/<TASK_ID>

# 5) 更新状态
curl -X PUT http://localhost:8080/tasks/<TASK_ID> \
  -H "Content-Type: application/json" \
  -d "{\"status\":\"in_progress\"}"

# 6) 删除，期望 204 无内容
curl -X DELETE http://localhost:8080/tasks/<TASK_ID>

# 7) 再查应 404
curl http://localhost:8080/tasks/<TASK_ID>

# 8) 非法创建（空标题），期望 400
curl -X POST http://localhost:8080/tasks \
  -H "Content-Type: application/json" \
  -d "{\"title\":\"   \"}"
```

成功创建时的响应示例：

```json
{
  "id": "3b2f0d6a-1c2e-4f3a-9d1b-8a7c6e5d4f3a",
  "title": "Write docs",
  "description": "Draft README",
  "status": "todo",
  "created_at": "2026-09-12T01:00:00Z",
  "updated_at": "2026-09-12T01:00:00Z"
}
```

## 4. Docker 构建和运行

作业验证命令：

```bash
# 构建镜像，标签 task-manager-api
docker build -t task-manager-api .

# 映射主机 8080 到容器 8080
docker run -p 8080:8080 task-manager-api

# 另开一个终端检查健康检查
curl http://localhost:8080/health
```

改端口示例：

```bash
# 容器内听 9090，主机仍映射 8080
docker run -p 8080:9090 -e PORT=9090 task-manager-api
```

Compose 一键启动：

```bash
docker compose up --build
```

看镜像是否非 root、是否多阶段：

```bash
# 构建日志里应能看到 builder 和最终两个 FROM
# 进容器看当前用户不应是 root
docker run --rm task-manager-api id
```

## 5. Minikube / Kubernetes 部署

Windows 上 `eval $(minikube docker-env)` 换成：

```powershell
minikube docker-env | Invoke-Expression
```

完整步骤：

```bash
# 1) 启动本地集群
minikube start

# 2) 打开 Ingress 插件，后面才能用 task-manager.local
minikube addons enable ingress

# 3) 让当前 shell 的 docker 打到 Minikube 里，镜像才能被 Pod 用到
eval $(minikube docker-env)

# 4) 构建集群能看到的本地镜像
docker build -t task-manager-api:local .

# 5) 创建 Namespace、ConfigMap、Deployment、Service、Ingress
kubectl apply -f k8s/

# 6) 看 Pod 是否 Running / Ready
kubectl get pods -n task-manager
kubectl wait --for=condition=ready pod -l app=task-manager-api -n task-manager --timeout=120s

# 7) 作业要求的总览（可截图）
kubectl get all -n task-manager
```

配域名：

```bash
# 查出 Minikube IP
minikube ip
```

把下面一行加到 hosts（Linux/macOS：`/etc/hosts`；Windows：`C:\Windows\System32\drivers\etc\hosts`）：

```
<MINIKUBE_IP> task-manager.local
```

访问：

```bash
curl http://task-manager.local/health
curl http://task-manager.local/tasks
```

排错：

```bash
# Ingress 是否有 ADDRESS
kubectl get ingress -n task-manager

# 看应用日志（请求日志、错误日志）
kubectl logs -n task-manager -l app=task-manager-api

# 描述 Pod，看探针失败原因
kubectl describe pod -n task-manager -l app=task-manager-api
```

清理：

```bash
kubectl delete -f k8s/
minikube stop
```

更短的清单说明见 [k8s/README.md](../k8s/README.md)。

## 8. 常见问题

1. **本机 `git push` 提示 Password authentication is not supported**  
   GitHub 不接受登录密码。用 `gh auth login --web` 或 Personal Access Token。

2. **Push 被拒绝，账号是别人的**  
   本机之前可能缓存了其他 GitHub 账号。用 `RichardTechDevops` 重新 `gh auth login`。

3. **连不上 github.com:443 / TLS handshake timeout**  
   网络到 GitHub 不通，先用浏览器打开 github.com 再推。

4. **Minikube 没装**  
   清单文件已经写好，装好 Minikube 后按第 5 节执行即可。

5. **Pod 起不来 ImagePullBackOff**  
   镜像要在 `minikube docker-env` 之后 build，并且 Deployment 使用 `imagePullPolicy: IfNotPresent`。

6. **task-manager.local 打不开**  
   确认 Ingress 插件已开、hosts 已写、`kubectl get ingress -n task-manager` 有 ADDRESS。
