# Task Manager API 代码说明

这份文档按目录讲解每一层代码在干什么、为什么这样写。源码里也有对应注释，可以对照阅读。

## 1. 整体结构

```
src/
├── app.py              # FastAPI 入口：中间件、异常处理、挂载路由
├── config.py           # 从环境变量读 PORT、LOG_LEVEL
├── logging_config.py   # 统一日志格式
├── storage.py          # 仓储接口 + 内存实现
├── models/
│   └── task.py         # 任务数据模型和校验
└── routes/
    ├── health.py       # GET /health
    └── tasks.py        # 任务增删改查
```

请求走这条链路：

1. `uvicorn` 加载 `src.app:app`
2. 请求日志中间件记下方法和路径
3. 路由函数调用 `repository`
4. Pydantic 模型负责入参校验和 JSON 输出
5. 校验失败或 404 由全局异常处理转成标准 JSON

分层的目的：路由不直接操作字典，存储可以以后换成数据库，不用改接口。

## 2. 入口 `src/app.py`

- `setup_logging()`：进程启动先配日志。
- `FastAPI(...)`：自动生成 `/docs`、`/redoc`、`/openapi.json`。
- `log_requests`：每个请求打一行 info；未捕获异常打 exception。
- `http_exception_handler`：404 等返回 `{"detail":"..."}`。
- `validation_exception_handler`：把 FastAPI 默认的 422 改成作业要求的 400。

为什么校验错误要手工挑字段：Pydantic 的 `ctx` 里可能有 `ValueError`，不能直接 `json.dumps`。

## 3. 配置和日志

`config.py` 只读环境变量：

| 变量 | 默认 | 谁会改它 |
| --- | --- | --- |
| `PORT` | `8080` | Dockerfile、docker-compose、K8s ConfigMap |
| `LOG_LEVEL` | `INFO` | 排错时改成 `DEBUG` |

`logging_config.py` 把日志打到 stdout，Docker / `kubectl logs` 都能直接看到。uvicorn 自带 access log 被压掉，避免和中间件日志重复。

## 4. 数据模型 `src/models/task.py`

对应作业模型：

| 字段 | 说明 |
| --- | --- |
| `id` | UUID 字符串，创建时自动生成 |
| `title` | 1～200 字符，不能全是空格 |
| `description` | 最长 2000，默认空串 |
| `status` | 只能是 `todo` / `in_progress` / `done` |
| `created_at` / `updated_at` | UTC，序列化成 `2026-01-01T00:00:00Z` |

三个模型分工：

- `TaskCreate`：POST 入参
- `TaskUpdate`：PUT 入参，字段都可选
- `Task`：返回给客户端的完整对象

`TaskStatus` 用枚举，非法值直接校验失败。

## 5. 存储 `src/storage.py`

- `TaskRepository`：协议（接口）。规定有哪些方法。
- `InMemoryTaskRepository`：用字典 `{id: Task}` 存在内存里。
- `repository`：进程内单例，所有请求共享。

注意：

- 重启进程或重建容器后数据会丢，这是作业允许的。
- `update_task` 用 `exclude_unset=True`，没传的字段保持原值。
- 以后要接数据库：新写一个类实现同样方法，把 `repository` 换成新实例即可。

## 6. 路由

### `health.py`

`GET /health` 返回 `{"status":"ok"}` 和 200。Docker 和 Kubernetes 探针都打这个地址。

### `tasks.py`

| 方法 | 路径 | 成功 | 失败 |
| --- | --- | --- | --- |
| GET | `/tasks` | 200 列表 | 无 |
| GET | `/tasks/{id}` | 200 对象 | 404 |
| POST | `/tasks` | 201 对象 | 400 |
| PUT | `/tasks/{id}` | 200 对象 | 404 / 400 |
| DELETE | `/tasks/{id}` | 204 空 body | 404 |

路由里只做“有没有这条记录”，字段合法性交给 Pydantic。

## 7. 容器和编排文件（也有注释）

- `Dockerfile`：多阶段构建、非 root、`PORT` 默认 8080。
- `docker-compose.yml`：本地映射 8080，并做 `/health` 探活。
- `k8s/*.yaml`：Namespace、ConfigMap、2 副本 Deployment、ClusterIP、Ingress。
- `.github/workflows/ci.yml`：Lint → 打标签 → 构建镜像 → Trivy。

## 8. 面试时容易被问到的点

1. **为什么内存存储还要 Protocol？** 作业要求“可扩展”，接口和实现分开，换数据库只改存储层。
2. **为什么 422 改成 400？** 作业表写的是 POST 201/400。
3. **时间为什么带 Z？** 作业示例是 `2026-01-01T00:00:00Z`。
4. **为什么健康检查单独一个文件？** K8s 探针和业务 CRUD 分开，探针失败不应和业务校验耦合。
5. **数据丢了怎么办？** 当前是演示实现；生产应把 `InMemoryTaskRepository` 换成数据库实现。
